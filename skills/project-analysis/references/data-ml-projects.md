# 数据、ML 与管道项目分析

> 译自 [project-analysis-skill](https://github.com/Bamzzo/project-analysis-skill)（MIT），基于上游 0d594be（2026-05-28）；中文译文，如有歧义以英文原文为准。

用于数据管道、分析、ETL/ELT、训练、评测、推理、notebook、模型服务、RAG 索引或实验类仓库。

## 首要问题

- 管道目标是什么：采集、转换、训练、评测、服务、索引，还是出报告？
- 主要输入与输出是什么？
- 数据集、特征、模型、产物与指标存放在哪里？
- 哪些配置控制运行？
- 执行方式是批处理、流式、交互式、定时，还是服务化？
- 哪些是确定性的，哪些依赖外部数据或模型行为？

## 需要定位的组件

- 管道运行器或编排入口
- 配置加载器与环境处理
- 数据连接器与存储路径
- 转换/特征代码
- 训练、评测、推理或索引代码
- 模型/供应商适配器
- 实验追踪与指标
- 产物序列化与版本管理
- 被当作运行入口的 notebook 与脚本
- 测试、黄金数据集、示例输入或 fixture

## 数据契约地图

对每个重要的数据集或产物，记录：

- 名称与路径/来源
- 生产者
- 消费者
- schema 或期望的列/字段
- 新鲜度假设
- 规模或采样策略
- 敏感数据风险
- 校验或质量检查

## 管道流程

追踪：

```text
源数据
-> 提取/加载
-> 清洗/归一化
-> 特征/记录构造
-> 模型/索引/报告步骤
-> 指标/产物/输出
-> 服务化或下游消费
```

## 常见失败模式

- 本地样本数据与生产数据不同。
- schema 是隐式的，或只写在 notebook 里。
- 随机种子、时间窗口或外部 API 让运行不可复现。
- 大数据路径被硬编码。
- 指标是在过期或被过滤的数据上算的。
- 模型产物缺少版本元数据。
- 评测数据泄漏进训练。
- notebook 代码才是真实管道，却没有测试。

## 验证

优先采用小而安全的检查：

- 对样本数据做 schema 校验
- 运行 dry-run 或极小样本管道
- 对转换逻辑运行单元测试
- 检查生成产物的元数据
- 对比文档中的指标与代码算出的指标
- 校验环境变量与存储凭据，但不打印密钥

## 建议的输出增补

对数据/ML 项目，额外加入：

1. 管道目的
2. 数据源与产物
3. Schema 与新鲜度契约
4. 训练/评测/推理流程
5. 可复现性与数据质量风险
6. 最小验证数据集或命令
