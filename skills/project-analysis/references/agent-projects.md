# Agent 项目分析

> 译自 [project-analysis-skill](https://github.com/Bamzzo/project-analysis-skill)（MIT），中文译文；如有歧义以英文原文为准。

当项目涉及 LLM、agent、工具调用、工作流、自动化、多智能体系统、RAG、computer use 或外部动作执行时使用。

## Agent 专属问题

- agent 的目标是什么？
- 它是纯对话、工具使用、工作流驱动、自主运行，还是人在回路？
- 它调用哪些模型？
- 模型供应商配置在哪里？
- prompt 如何构造？
- 工具在哪里注册？
- agent 如何选择工具？
- 工具调用在哪里执行？
- 返回给模型的观察结果是什么？
- 状态/记忆如何存储？
- 什么机制阻止无限循环？
- 哪些动作是只读的，哪些是破坏性的？
- 哪些操作需要用户确认？

## 常见 Agent 分层

```text
用户输入
-> 意图/任务解析
-> 规划器
-> 工具选择
-> 工具调用序列化
-> 执行器/路由
-> 外部系统/工具
-> 观察/状态更新
-> 评估
-> 重新规划或结束
```

## 需要定位的组件

- 模型 client / 适配器
- prompt 模板
- 规划器 / 编排器 / 图运行器
- 工具 schema 定义
- 工具注册表
- 工具执行器
- 状态存储 / 记忆
- 观察结果构造器
- 事件流 / 回调处理
- 安全检查 / 审批
- 评估或环检测
- 日志与追踪

## 工具调用契约

对每个重要工具，记录：

- 工具名
- 暴露给模型的描述
- 输入 schema
- 输出 schema
- 副作用
- 错误格式
- 必需的前置条件
- 结果中是否包含后续步骤需要的 id
- 该工具是否可安全重试

## 观察质量

好的观察结果应该：

- 结构化。
- 包含状态变化或相关的当前状态。
- 包含后续动作需要的稳定 id/handle。
- 包含警告。
- 足够小，模型能消费。
- 不把关键数据藏在巨大载荷里。

## Agent 失败模式

- 模型/供应商路由错误
- 缺少 API key 或 base URL
- prompt 没有暴露需要的工具
- 一次暴露太多工具
- 工具 schema 过于模糊
- 工具结果缺少下一步所需的 id
- 模型在同一个工具上打转
- 模型忽略观察结果
- 执行器静默吞掉错误
- 外部动作成功，但观察结果已过期
- 破坏性动作缺少预览/审批

## 安全与控制

查看是否存在：

- 只读 vs 写入类工具
- 人工审批门
- dry-run / 预览模式
- 最大步数限制
- 超时与重试行为
- 工具白名单
- 密钥脱敏
- 审计日志
- 回滚或 checkpoint 策略
