# 库、SDK、CLI、插件与扩展分析

> 译自 [project-analysis-skill](https://github.com/Bamzzo/project-analysis-skill)（MIT），中文译文；如有歧义以英文原文为准。

用于可复用包、SDK、命令行工具、插件、扩展、框架集成或开发者工具。

## 首要问题

- 消费者是谁：终端用户、开发者、另一个包、运行时宿主，还是插件管理器？
- 公共 API 或命令面是什么？
- 哪些属于内部实现细节？
- 包如何构建、版本化、发布与撰写文档？
- 存在哪些兼容性承诺？
- 哪些示例或测试定义了预期行为？

## 需要定位的组件

- 包元数据与入口
- 公共导出
- CLI 命令解析器与子命令
- 插件 manifest 或扩展激活点
- 配置 schema
- 示例与文档
- 针对公共行为的测试
- 构建与发布脚本
- Changelog 或版策略

## 公共面地图

对每个公共 API、命令或扩展点，记录：

- 名称
- 目的
- 输入/选项
- 输出/结果
- 错误
- 副作用
- 稳定性或兼容性顾虑
- 用法示例
- 测试覆盖

## 流程模式

CLI：

```text
argv
-> 命令解析器
-> 配置/env 加载
-> 命令处理器
-> 核心库
-> 文件系统/网络/进程副作用
-> stdout/stderr/退出码
```

库/SDK：

```text
消费者 import
-> 公共 API
-> 校验/配置
-> 核心实现
-> 适配器/外部依赖
-> 返回值/错误
```

插件/扩展：

```text
宿主运行时
-> manifest/激活
-> 扩展入口
-> 注册的命令/钩子/工具
-> 宿主 API 调用
-> 用户可见或系统可见的效果
```

## 常见失败模式

- 文档描述了并未导出的 API。
- 测试覆盖内部实现而不是公共行为。
- CLI 在部分失败后仍以成功退出。
- 配置优先级不清晰。
- 插件激活依赖隐藏的宿主状态。
- 发布产物与源码行为不同。
- 破坏性变更未反映在版本号上。
- 错误信息缺乏可行动的上下文。

## 验证

优先采用：

- 检查包的导出或生成的类型
- 运行文档中的示例
- 运行 CLI 帮助与一个无害命令
- 运行公共 API 测试
- 在安全时本地构建/打包
- 检查发布工作流与已发布产物的配置

## 建议的输出增补

对库、SDK、CLI、插件或扩展，额外加入：

1. 公共面
2. 消费者使用路径
3. 配置与错误契约
4. 构建与发布路径
5. 兼容性风险
6. 基于示例的验证
