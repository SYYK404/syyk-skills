# 安全敏感型项目分析

> 基于 [project-analysis-skill](https://github.com/Bamzzo/project-analysis-skill)（MIT）commit 0d594be（2026-05-28）改编，含内容修改与增补。

用于安全敏感评审、认证/授权分析、密钥处理、依赖/供应链风险、外部动作执行系统，或面向审计的项目分析。这是代码与架构层面的评审辅助，**不能替代正式的渗透测试**。

## 首要问题

- 哪些资产、用户、租户、数据、凭据或外部系统需要保护？
- 信任边界在哪里被跨越：UI/API、服务/服务、模型/工具、worker/job、数据库、文件系统、云，或桌面操作系统？
- 用户、服务、agent 或工具如何被认证？
- 授权如何执行，是集中式还是分散式？
- 密钥在哪里加载、存储、记录日志、脱敏、轮换，以及传给子进程？
- 哪些输入是不可信的，在哪里被校验、解析、转义或沙箱化？
- 哪些第三方包、生成产物、CI 工作流与部署路径会影响可信构建？

## 需要定位的组件

- 认证中间件、守卫、策略、会话、token 处理与权限检查
- 用户、角色、租户、组织与资源归属模型
- 输入校验器、序列化器、解析器、上传处理器与反序列化器
- 密钥/配置加载、环境变量模板、vault/参数存储引用
- 日志、遥测、追踪与错误上报
- 外部 API client、webhook 处理器、回调、队列与后台任务
- 工具/动作注册表、审批门、沙箱化与 dry-run 逻辑
- 依赖清单、锁文件、CI 工作流、发布脚本与容器镜像

## 风险区域

- 缺少路由/中间件覆盖导致的认证绕过
- 跨租户或跨资源所有者的对象级授权缺口
- 密钥被提交、回显、记入日志，或被传入宽泛的进程环境
- 不安全的文件路径、压缩包解压、shell 执行、模板渲染或反序列化
- SSRF、开放重定向、webhook 伪造、弱签名校验或重放风险
- 过宽的 CORS、CSRF 缺口、不安全的 cookie 或 token 存储问题
- 依赖混淆、未固定版本的动作/镜像、可变 tag，或生成产物漂移
- 允许在没有预览、审批或审计日志的情况下执行破坏性动作的 agent/工具系统

## 安全规则

- 不要打印密钥、token、私钥、完整连接串、敏感记录或利用载荷。
- 优先做防御性分析与校验，而不是实际执行利用。
- 除非明确要求并限定范围，不要运行扫描器、fuzzer、网络探测、凭据测试或破坏性载荷。
- 按证据与置信度标注安全问题：confirmed（已确认）、likely（很可能）、possible（可能）、open（待确认）。

## 验证

优先采用：

- 路由/中间件覆盖情况检查
- 权限策略测试，或识别缺失的测试
- 密钥脱敏与日志审查
- 依赖与锁文件检查
- CI/发布工作流审查
- 针对校验器、认证守卫与策略检查的安全本地单元测试
- dry-run 或只读的工具/动作检查

5. 供应链与发布风险
