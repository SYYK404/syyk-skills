# 数据库与持久化项目分析

> 基于 [project-analysis-skill](https://github.com/Bamzzo/project-analysis-skill)（MIT）commit 0d594be（2026-05-28）改编，含内容修改与增补。

用于数据库密集型应用、schema 仓库、迁移、ORM、持久化层、数据访问模块，或正确性依赖已存储状态的项目。

## 首要问题

- 使用了哪些数据库或存储引擎？
- schema 的真实来源是什么：迁移、ORM 模型、SQL 文件、内省、生成类型，还是文档？
- 本地、测试、staging、production 环境如何隔离？
- 迁移如何创建、排序、应用、回滚与验证？
- seed、fixture、factory 与示例数据在哪里定义？
- 哪些事务、约束、索引与一致性假设在保护数据？
- 哪些数据是敏感的、按租户隔离的、用户拥有的、被缓存的或被派生的？

## 需要定位的组件

- 迁移目录与迁移运行器配置
- ORM 模型、生成的 client、schema 文件与查询构建器
- 数据库连接/配置加载
- repository/数据访问模块
- seed 脚本、fixture、factory 与本地开发容器
- 查询文件、存储过程、触发器、函数、视图与物化视图
- 备份、恢复、复制或保留策略脚本
- 针对迁移、repository 与数据不变量的测试

## 契约地图

对每个重要的表、集合、topic 或持久化产物，记录：

- 名称与存储技术
- 生产者与消费者模块
- 主键与重要标识符
- 必需字段与约束
- 索引或访问模式
- 归属/租户边界
- 生命周期：创建、更新、归档、删除
- 迁移或兼容性风险

## 安全规则

- 除非明确要求，不要运行迁移、seed 脚本、破坏性 SQL、写查询、reset 命令或类似生产的连接命令。
- 优先使用 schema 检查、迁移 dry-run、生成 SQL 审查、测试库检查，或针对本地 fixture 的只读查询。
- 对凭据、连接串、token、账号 id 与敏感样本记录做脱敏。
- 在只检查了代码的情况下，区分"声明的 schema"与"实际部署的 schema"。

## 常见失败模式

- ORM 模型与迁移不一致。
- 迁移不可逆或不是幂等的。
- 本地 seed 掩盖了生产的非空性、数据量或租户形态问题。
- 索引与查询模式不匹配。
- 多步写入缺少事务。
- 软删除、归档或保留行为不一致。
- 生成的 client 或 schema 类型已过期。
- 后台任务假设了数据库并未保证的数据新鲜度或顺序。

## 验证

优先采用：

- 检查迁移历史与顺序
- 在安全时对本地/测试库做 schema 校验或迁移状态检查
- 运行 repository 测试或数据访问单元测试
- 审查生成的 SQL 或 ORM 查询输出
- 针对主要被追踪的查询检查索引
- 校验 seed/样本数据是否覆盖被追踪路径

## 建议的输出增补

对数据库或持久化密集型项目，额外加入：

1. 存储技术与环境地图
2. Schema 真实来源
3. 迁移与回滚路径
4. 数据契约地图
5. 查询与事务流程
6. 数据完整性与敏感性风险
7. 安全验证命令
