# 收藏导出（抖音 / B站 / 掘金 / 小红书 / 小黑盒）

帮用户把自己账号的收藏完整导出为本地文件。核心原则：**登录态来自用户本人（已登录的会话或用户扫码），数据只写本地文件，不经过任何第三方**。

## 环境要求

需要一个能操控**用户已登录会话所在浏览器**的自动化能力（浏览器扩展注入、CDP 附加、Playwright、内置浏览器均可）。ZCode 环境用 browser-use 内置浏览器，先加载 `browser-use:control-browser` 技能。

环境里没有浏览器自动化能力时，如实告知并停止——不要降级为脚本自建 HTTP 会话模拟登录：收藏接口强依赖登录态与风控，极易触发封禁。

## 总体流程

1. 绑定目标站点页面（见「标签选择」）；未登录则引导用户登录（见各平台参考文件）。
2. 按平台路线提取全部收藏，**边提取边落盘**（每轮循环追加保存，中途失败不丢已抓数据）。
3. 用 `scripts/export-formats.mjs` 合并产出最终 JSON/Markdown/TXT。

## 平台路由

| 平台 | 提取路线 | 详细参考 |
|---|---|---|
| 抖音 | DOM 滚动 + 增量提取（内滚容器） | [references/douyin.md](references/douyin.md) |
| B站 | 页面上下文调用 B站自有 API（收藏夹 + 合集两种） | [references/bilibili.md](references/bilibili.md) |
| 掘金 | 收藏集 SSR 流式渲染，滚动等流推完再从 DOM 提取 | [references/juejin.md](references/juejin.md) |
| 小红书 | DOM 滚动提取虚拟列表卡片（API 有签名壁垒，只读 DOM 不碰接口） | [references/xiaohongshu.md](references/xiaohongshu.md) |
| 小黑盒 | 页面上下文 fetch 重放收藏 API（offset 分页，无签名壁垒） | [references/xiaoheihe.md](references/xiaoheihe.md) |

进入某平台前**必须先读对应参考文件**——每个平台的关键选择器、接口参数都在里面，不要凭记忆猜。

## 通用执行协议

**标签选择**：
- 每批操作前，列出自动化范围内的全部标签页（含用户自己打开的可见页面），按域名/URL 匹配后绑定目标标签。
- **用户说「已登录 / 已经打开了」时，优先接管复用用户已打开的目标站点页面，不要新开重复标签**。
- 宿主端脚本调用可能是无状态的（每次调用是新的执行上下文）：跨调用不要复用内存里的浏览器/标签页对象，每次按标签页事实（id、URL）重新恢复绑定。持久边界是浏览器里的标签页，不是脚本变量。

**账号身份**：
- 需要 UID / 账号标识时，一律从**站点顶部导航的头像 / 个人主页链接**读取（各站选择器见参考文件）。内容区的用户链接（文章卡片、推荐流、评论区）指向的是内容作者，不是登录用户，禁止用来当身份。
- 身份存疑时（如页面昵称与用户预期不符），向用户展示当前识别到的账号名再继续。

**浏览器调用**：
- 单次页内脚本保持短小：一次调用只做一件小事（滚动一次、提取一次、请求一页）。循环与延时由宿主端脚本驱动——长驻页内脚本会阻塞页面且有超时风险。
- 导航后等待页面就绪（domcontentloaded 或等价状态）再观察。

**登录**（需要用户参与，脚本无法代替）：
- 验证码（滑块/拼图）无法自动化，提示用户在浏览器中手动完成。
- 二维码登录：页面出现二维码后请用户扫码，用轮询循环检测登录态（每 5s 查一次页面特征，最多 ~100s）。检测条件选「登录后才消失/出现」的元素，且**基于元素可见性判断**（如按钮 `offsetParent` 为空）——不要用全文文本包含判断，SPA 隐藏组件的文本会残留导致永远检测不到。二维码过期时先刷新再继续轮询。

**提取循环的停止条件**（三平台通用）：
- 连续 N 轮（4~7，按平台）无新增 → 停止。
- 有官方计数时（页面显示的总数），达到计数即提前停止。
- 实抓数 < 官方计数是**正常现象**：差额是已删除/已失效条目，页面计数包含但列表不渲染。不要为此反复重试，如实记录差额即可。

**数据结构**：每个平台/收藏夹存一个原始 JSON 文件（含 `platform`、分组字段、`exportTime`、`data[]`），条目统一有 `title`、`url`，其余字段按平台（`author`/`uploader` 等）。去重一律用 `Map<url, item>`。

## 导出

提取完成后，把原始 JSON 所在目录交给打包脚本：

```bash
node <本技能目录>/scripts/export-formats.mjs <原始JSON目录>
# 可选：生成交互式总览页
node <本技能目录>/scripts/build-overview-html.mjs <原始JSON目录>
```

前者在该目录下生成 `final/`：每个平台一份 `xxx_favorites.{json,md,txt}`（MD 按收藏夹分节）+ 全平台合并的 `all_favorites.json`。

后者在目录下生成 `收藏总览.html`——自包含单文件（1745 条约 460 KB，数据内嵌、离线可用），支持搜索、平台/收藏夹筛选、热度/时间排序、跨收藏夹去重、一键复制链接。用户想「筛选和查看」收藏时主动提供。用户要求其他数据加工（去重分析、按作者统计等）时，以此页为基线扩展，不要从零重写。
